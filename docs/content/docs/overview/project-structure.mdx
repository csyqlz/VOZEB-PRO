# 项目结构与流程

本文用于回答“功能在哪里、请求怎么走、数据保存到哪里”。项目采用 Next.js 全栈结构，浏览器只负责界面和瞬时状态；业务规则、密钥、模型路由、计费和持久化全部留在服务端。

## Web 目录职责

| 路径                           | 职责                                                                 |
| ------------------------------ | -------------------------------------------------------------------- |
| `web/src/app/(user)/`          | 登录后的 Agent、图片、视频、Canvas、短剧、素材、提示词和个人中心页面 |
| `web/src/app/admin/`           | 管理员入口、运营后台和初始化配置中心                                 |
| `web/src/app/api/`             | HTTP 入参、鉴权、服务调用和 `{ code, data, msg }` 响应映射           |
| `web/src/components/`          | 全局布局、通用业务组件和管理后台视图                                 |
| `web/src/hooks/`               | 多页面复用的生成、会话、复制、下载和状态同步逻辑                     |
| `web/src/services/api/`        | 浏览器到本站 Route Handler 的类型化请求                              |
| `web/src/stores/`              | 登录用户、主题、公开配置和素材等共享客户端状态                       |
| `web/src/lib/*.ts`             | Canvas、短剧、素材、模型、支付和创作运行时领域契约                   |
| `web/src/lib/auth/`            | Session、用户、权限、积分和公开设置入口                              |
| `web/src/lib/server/`          | 业务服务、任务编排、Provider 适配、计费、媒体与安全逻辑              |
| `web/src/lib/server/database/` | PostgreSQL schema、参数化 Repository 和文件 Provider 回退            |
| `web/src/styles/`              | 全局布局和跨页面主题样式，页面私有样式仍由组件管理                   |
| `web/src/**/*.test.ts(x)`      | 与实现同域放置的 Vitest 单元和契约测试                               |

## 标准页面请求

```mermaid
flowchart LR
    UI["React 页面或组件"] --> CLIENT["services/api 请求"]
    CLIENT --> ROUTE["app/api Route Handler"]
    ROUTE --> AUTH["Session 与权限校验"]
    AUTH --> SERVICE["lib/server 业务服务"]
    SERVICE --> REPO["database Repository"]
    REPO --> PG[("PostgreSQL")]
    SERVICE --> RESULT["code / data / msg"]
    RESULT --> CLIENT
    CLIENT --> STORE["页面状态或 Zustand"]
    STORE --> UI
```

Route Handler 不直接堆业务规则或 SQL。页面也不直接连接数据库或外部模型，真实密钥只在服务端解密和使用。

## Agent 与生成任务

```mermaid
flowchart TD
    INPUT["用户文字与参考素材"] --> SKILL["解析所选 Skill 与入口策略"]
    SKILL --> MODE{"智能规划是否开启"}
    MODE -->|开启| PLAN["默认文本模型内部规划"]
    MODE -->|关闭且已选模型| MANUAL["保留用户模型与明确参数"]
    PLAN --> VALIDATE["Skill、能力、参考素材与参数校验"]
    MANUAL --> VALIDATE
    VALIDATE --> IDEMPOTENT["按 clientRequestId 创建幂等任务"]
    IDEMPOTENT --> ROUTER["逻辑模型路由与候选渠道"]
    ROUTER --> UPSTREAM["只向上游提交一次"]
    UPSTREAM --> POLL["查询同一上游任务状态"]
    POLL --> OUTCOME{"任务结果"}
    OUTCOME -->|成功| NORMALIZE["媒体下载、时长或格式规范化"]
    OUTCOME -->|明确失败| FAILED["失败、退款并等待用户重试"]
    NORMALIZE --> MEDIA["媒体登记与稳定 storageKey"]
    MEDIA --> MESSAGE["当前助手消息返回结果"]
    MESSAGE --> POINTS["刷新积分与生成记录"]
    FAILED --> RETRY["用户点击重试后创建新 attempt"]
```

平台规划提示词、模型选择理由、创作简报、物料计划和视觉复盘只用于内部执行，不写入生成型对话。用户手动选择模型并给出明确提示词时，不再由规划器改选模型，但仍必须经过 Skill、能力、参考素材、计费和安全校验。

轮询只查询已经创建的任务，不能因为查询超时或暂未完成而再次调用创建接口。只有上游明确返回失败并且用户点击“重试”，才允许创建新的 attempt，避免重复消耗上游额度。

## 媒体存储与访问

```mermaid
flowchart LR
    FILE["上传或生成的原文件"] --> CHECK["格式、大小、归属校验"]
    CHECK --> NAME["日期时间 + UUID 重命名"]
    NAME --> SWITCH{"外部存储开关"}
    SWITCH -->|关闭| LOCAL["服务器本地数据目录"]
    SWITCH -->|开启| S3["S3 兼容对象存储"]
    LOCAL --> REGISTRY["媒体登记：用户、来源、原名、关联"]
    S3 --> REGISTRY
    REGISTRY --> KEY["业务只保存稳定 storageKey"]
    KEY --> API["鉴权媒体 API"]
    API --> PREVIEW["页面 WebP 预览"]
    API --> ORIGINAL["下载原始格式文件"]
```

外部存储开关只影响新文件写入位置；历史文件始终按自身 `storage_provider` 读取。删除前必须检查创作会话、素材库、Canvas、短剧和生成记录引用，不能留下静默失效资源。

## 积分与退款

```mermaid
flowchart LR
    REQUEST["创建生成任务"] --> PRICE["计算模型和参数积分"]
    PRICE --> BALANCE{"余额足够"}
    BALANCE -->|否| REJECT["对话内提示积分不足"]
    BALANCE -->|是| DEBIT["原子扣费并写流水"]
    DEBIT --> EXECUTE["执行上游任务"]
    EXECUTE -->|成功| SETTLE["记录结果与实际消耗"]
    EXECUTE -->|失败或取消| REFUND["幂等退款"]
    SETTLE --> SYNC["刷新右上角积分"]
    REFUND --> SYNC
```

## 生产部署

```mermaid
flowchart LR
    USER["浏览器"] --> HTTPS["HTTPS 域名"]
    HTTPS --> NGINX["宝塔 Nginx 或其他反向代理"]
    NGINX --> APP["VOZEB PRO :3000"]
    APP --> PG[("PostgreSQL 16")]
    APP --> LOCAL["本地持久媒体目录"]
    APP --> OSS["可选 S3 / OSS"]
    APP --> AI["文本、图片、视频、音频上游"]
    APP --> PAY["可选支付与 SMTP 服务"]
```

标准 Compose 自带 PostgreSQL；宝塔 Compose 使用宿主机 PostgreSQL；外部数据库与低内存 Compose 只运行应用。所有模式共用同一代码和数据契约。

## 查问题的最短路径

```mermaid
flowchart LR
    BUG["页面问题"] --> PAGE["对应 page.tsx 或组件"]
    PAGE --> HOOK["同目录 Hook / Store"]
    HOOK --> CLIENT["services/api"]
    CLIENT --> ROUTE["app/api route.ts"]
    ROUTE --> SERVICE["lib/server 服务"]
    SERVICE --> REPO["Repository 或任务 Store"]
    REPO --> TEST["同域测试与数据库契约"]
```

例如 `/create` 图片任务历史异常，应从页面私有 Hook 找到 `services/api/creative.ts`，再进入 Creative Conversation / Agent Run Route、任务 Store、生成记录和媒体登记；不要在页面层直接增加数据库或上游兼容分支。底层 `services/api/image.ts` 与 `api/image-tasks` 仍负责真实图片子任务，不代表存在独立图片工作台页面。
