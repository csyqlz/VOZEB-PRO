## 健康检查

- `GET /api/health/live`：只检查 Web 进程是否能响应，Docker Compose 使用该地址，避免数据库短暂异常导致应用容器反复重启。
- `GET /api/health/ready`：检查数据库连接、表结构、加密密钥和首个管理员；未完成安装或依赖异常时返回 HTTP `503`，用于反向代理、负载均衡和外部监控。
- `/api/install/status`：面向安装页面的安全状态，不应作为生产告警依据。

## 计划任务

配置至少 32 个字符的 `VOZEB_PRO_MAINTENANCE_TOKEN`，每 5 分钟调用：

```bash
curl -fsS -X POST \
  -H "Authorization: Bearer $VOZEB_PRO_MAINTENANCE_TOKEN" \
  https://vozeb-pro.example.com/api/maintenance/billing-orders/expire
```

宝塔使用计划任务，Docker 使用宿主机 Cron，云平台使用 Scheduler。任务可以重复执行，多实例会通过数据库锁避免重复关闭订单。

## 备份与恢复

- 本机 `docker-compose.local.yml` 可用 `scripts/node-bundle.mjs` 制作完整迁移包或不含生产数据的新节点模板；完整模式整合现有离线 PostgreSQL／本地媒体／对象存储恢复点、应用与数据库镜像及加密 `.env`。恢复具备哈希预检和确认 ID，换域名时重新构建，App 先仅绑定回环地址且不自动启动 Worker。该脚本不覆盖外部数据库、宝塔拓扑、跨架构和换对象存储桶；真实异地恢复、DNS／HTTPS／支付回调、媒体与任务切流仍需演练。

- 后台“数据备份”导出与恢复要求当前管理员 Session 具备 `system.manage`，不再逐次要求当前密码或 TOTP；导出通过无请求体的独立 POST 返回 `private, no-store` 脱敏业务数据，恢复 multipart 只提交备份文件。该数据只用于 `account-config` 合并恢复账号、非敏感设置、公共提示词和生成记录；导入不会删除备份中缺失的用户或记录，PostgreSQL 使用事务与锁，文件 Provider 失败时回滚原快照。业务 JSON 不包含 Canvas、素材、媒体原件、短剧、订单和对象存储完整清单，不能作为整库灾难恢复包。
- 管理员 MFA Secret 不进入常规业务备份；恢复业务包不能替换、启用或关闭服务器现有 MFA。管理员丢失身份验证器时可在服务器执行 `pnpm -C web reset:admin-mfa -- --username <账号>`，命令会清除目标管理员 MFA 并撤销其全部 Session；文件 Provider 修改前保存恢复副本，PostgreSQL 使用事务。该命令是账号访问恢复能力，不替代完整灾难恢复演练。
- PostgreSQL 使用数据库平台或 `pg_dump` 做整库备份；支付流水、支付配置和密钥不依赖业务 JSON 备份。
- 本地媒体目录、S3/OSS 对象和对象存储配置分别备份；不要只备份数据库后假设媒体能够恢复。
- 至少保留每日自动备份、异地副本和定期恢复演练。备份任务成功不等于恢复可用。

## 异步生成与计费闭环

图片、视频、音频和 Agent 任务需要在真实渠道下验证排队、超时、取消、重试、断线恢复、重复提交和卡死任务接管。每个任务都应能与原消费流水、失败退款、用户余额、生成记录和媒体登记逐项核对；重启和多实例竞争不能造成重复扣费、重复资产或“任务失败但积分未退”。

当前代码已提供页面定向唤醒、独立生成 Worker、PostgreSQL 租约、心跳就绪检查、HMAC 回调幂等登记和 `needs_review` 管理员接管。普通 Agent 生成完成后可由持久 Worker继续内部复盘，进程重启后仍可恢复，复盘最终不可用不会撤销成功媒体；`needs_revision` 只保存内部建议，不会自动重新创建上游媒体任务。用户端 SSE 断线时不按固定失败次数终止，而是继续等待 EventSource 自动重连并复用单个服务端 Run 状态核对；切换对话也只停止当前页面观察，不改变后台 Run。Planner 只按 Surface 与能力筛选已验证模型和用户显式 Skill，完整发送会话上下文、参考资产与项目快照，不再由平台叠加固定字符、输出 token 或节点数量上限；真实供应商上下文窗口和拒绝行为仍需单独验收。PostgreSQL Run 事件使用事务内 `NOTIFY` 和独立 `LISTEN` 连接即时唤醒 SSE，现有轮询只承担通知丢失兜底。本地协议矩阵已按注册能力核对任务完成、媒体解析/落盘、资产登记、查询路径、模型目录和鉴权头，并覆盖 Worker 查询、人工确认失败与退款。这些结果不能替代默认 Docker、宝塔、低内存、外部数据库、多实例和真实供应商下的无人页面运行、通知丢失、接管竞争、媒体登记与账本证据。

混合模型渠道可以按模型保存 OpenAI、Gemini、Seedance 2.0 或兼容协议与创建/查询路径，但代码适配不能替代供应商文档和真实密钥验收。上线前应逐渠道保存实际模型目录响应、分页证据及文本/图片/视频最小调用结果；上游未公开目录或使用不透明模型名时，必须由管理员维护模型能力与路由，不能把名称猜测当成生产证据。

PostgreSQL 在线扣费已使用定向的用户、套餐、每日钱包、额度和流水查询，完整认证快照只保留给备份或兼容路径。系统渠道的本地计费身份由服务端绑定用户、业务请求、逻辑模型、渠道、上游模型和调用类型生成，普通用户提交的计费幂等头不会直接成为流水键；流水请求指纹会拒绝同身份不同参数的重放，零积分调用也保留可撤销记录。退款补偿每次维护调度只执行一次真实尝试，后续节奏由外部 Scheduler 决定，不再内置“8 次后人工”或指数退避；Agent 文本字数要求只转发用户本轮约束，不再按固定三次重写并截断成功内容，邀请码与 CDK 也改用数据库唯一身份生成。该实现仍必须通过真实生成并发、锁等待、超时退款和余额对账验收；重试、人工补账、上游暂停和降级规则必须来自供应商公开约束、管理员配置或已有且可验证的资源保护契约，不能新增拍脑袋的固定次数、延时或输出上限。

- **数据生命周期**：后台已提供显式维护入口，按管理员开关和批次清理具有明确技术到期时间的 Session、邮箱验证码、生成任务和无引用临时媒体；普通在线读写不再顺手执行无界清理，PostgreSQL 与文件 Provider 都使用稳定排序和有界批次。上线前仍须为对话、长期媒体、WebP 变体、审计、积分、订单、支付记录和 S3 对象确定适用地区的保留期限、用户删除触发、法律保留例外、调度负责人和删除结果核验，代码不会猜测这些制度。
- **存储与网络成本**：按本地磁盘、OSS 请求、存储容量、外网下行、CDN/代理和备份副本建立成本监控，设置容量、带宽和对象存储账单预警；S3 开关本身不等于成本治理。
- **故障沟通**：准备状态页或公告替代方案、维护通知模板、生成失败/退款延迟/上游停服的用户文案和客服升级路径，明确谁有权暂停某个模型或支付渠道。
- **无障碍与浏览器支持**：在目标浏览器和移动端完成键盘操作、焦点顺序、表单错误、对比度、动态状态播报、媒体替代文本和下载行为验收，并公布最低支持范围。
- **通知可达性**：验证注册、验证码、密码重置、支付结果和故障通知的实际送达；配置发信域名 SPF/DKIM/DMARC，监控退信与投诉，保留模板版本，并为通知供应商故障准备人工或站内公告兜底。
- **环境与回滚**：开发、预发布和生产必须隔离数据库、对象存储桶、支付商户、模型密钥、维护令牌和回调域名；每次发布都要有迁移前备份、冒烟检查、可替换镜像和回滚后数据兼容记录。
- **成本熔断**：后台已支持按实际积分计价配置单任务、单用户每日和全站每日生成成本上限，默认 `0` 表示不限制；PostgreSQL 使用事务级全站预算锁，文件 Provider 使用既有串行事务，退款释放当日占用。上线前仍须按真实模型价格与毛利设置生产值，并补齐供应商余额、媒体处理、存储与外网下行告警；积分保护不能代替上游配额、盗号识别和异常渠道暂停。
- **商业证据**：每项 P0/P1 控制项都应登记负责人、截止时间、环境、证据链接、复核人和复核日期；没有真实支付、通知、恢复、压测或安全演练证据时，仍标记为未完成。

这些控制项应落到负责人、截止时间、证据链接和复核结果；没有证据时继续标记为未完成，不要因为已有接口、后台开关或自动化测试就视为商业闭环。

### 上线判定

1. 任一阻断项没有负责人、复核人和真实证据时，只能进入内部或封闭测试，不能宣称正式商业上线。
2. 代码测试、健康探针、后台开关和配置页面只能证明技术基础，不能替代支付商、OSS、邮件、代理、恢复和人工流程验收。
3. 灰度期间每周复核生成成功率、退款率、单位作品成本、存储增长、投诉和供应商异常；发现资金、隐私或内容安全风险时立即暂停对应渠道并保留用户数据与财务记录。
