# 商业落地缺口

VOZEB PRO 已具备图片、视频、短剧、Canvas、Agent、积分、商品、支付接入、服务端媒体和 S3 兼容存储等产品基础能力。但自动化测试通过、后台有配置项或接口可以调用，都不能单独证明已经具备正式商业运营条件。

本文记录当前仍需要真实环境、外部供应商或人工流程完成的事项。未取得负责人、复核人和可复现证据前，状态保持“未完成”，只能进行内部或封闭测试。部署执行细节见[生产上线基线](/docs/overview/production-readiness)。

## 当前实现边界

以下内容是代码当前提供的技术基础，不代表对应的商户、合同、资质或生产验收已经完成：

- 支付代码当前包含 Stripe Checkout、支付宝电脑网站支付、微信支付 v3 Native、PayPly 自定义接口和人工确认；项目没有独立的 PayPal 适配器，PayPly 不能按 PayPal 对外描述。
- 自动退款当前按整笔订单处理。部分退款、部分积分回收、多次退款累计和拒付处理仍需要先确定财务规则，再分别完成服务端、支付商和对账验收。
- 后台业务备份是脱敏业务数据的导入/导出能力，不等于 PostgreSQL 整库、支付敏感配置、加密密钥、本地媒体和 S3/OSS 对象的可恢复备份。
- 经营看板提供调用、模型、入口、内容类型、积分、累计订单成交、活动/用券成交和邀请注册等摘要，不等于正式的收入、成本、税费、毛利、留存或财务对账报表。
- S3 兼容配置、媒体迁移和签名读取是存储技术能力，不等于对象存储合同、访问权限、生命周期、备份、带宽成本和供应商 SLA 已经确认。
- PostgreSQL 后台 CDK 列表已具备数据库侧分页、筛选和聚合统计，降低大数据量下的管理页读取压力；这只是查询性能基础，仍需在生产等价数据量下完成后台 P95、慢查询和连接池验收。
- 管理员 TOTP MFA 已支持密文保存、登录挑战、其他 Session 撤销、备份脱敏和服务器恢复命令；这不等于生产管理员已逐个绑定真实设备、恢复流程已演练或异常登录与高风险操作复核已经建立。

因此，下面的“已接入”只能用于说明实现范围；只有在[上线证据矩阵](#商业上线证据矩阵)补齐负责人、复核人和真实证据后，才能把对应事项从商业上线清单中移除。

## 代码无法替代的商业交付物

以下交付物不属于某个接口或页面的“已完成”状态，必须由项目方、部署方、财务、客服和法律负责人分别交付并留档：

- **经营与交易**：运营主体、服务地区、域名/网络资质、支付商户和退款权限、发票税务口径、对账责任人，以及套餐价格、积分兑换、模型成本、存储/带宽和毛利表。
- **法律与内容**：审核后的隐私政策、服务条款、退款规则、用户内容授权、AI 生成标识、年龄/地区限制、可接受使用政策、侵权投诉、举报复审、申诉和下架流程。
- **安全与权限**：管理员清单和职责分离、MFA 设备启用与恢复演练、异常登录和高风险操作复核、密钥与证书轮换、越权和私有媒体暴露处置、漏洞披露、依赖/镜像/密钥扫描记录。
- **运维与灾备**：生产监控、告警和值班升级表，PostgreSQL/本地媒体/OSS/支付配置/加密密钥备份，新环境恢复报告，以及 RPO、RTO、保留周期和恢复后数据核对。
- **用户服务**：客服入口、服务时间、支付和退款升级路径、隐私请求时限、通知送达、退信处理、状态页或维护公告方案。
- **供应商与退出**：模型、支付、SMTP、对象存储和通知供应商的合同、价格、配额、数据区域、SLA、停服通知、迁移导出和替代渠道方案。

任何一项只有代码、自动化测试、健康探针或后台开关，而没有负责人、截止时间、复核人、环境和可复现证据时，仍应标记为“未完成”。这些交付物是正式商业上线的前置条件，不应由开发人员用接口可调用来代签。

## P0 上线阻断项

以下事项在正式收费和公开运营前必须完成：

- **真实支付验收**：每个实际启用的渠道完成下单、成功/失败支付、取消、超时、重复/乱序/迟到回调、整单退款、退款失败恢复和账单对账。当前自动退款按整笔订单处理；部分退款必须先确定订单、积分回收和会计口径。
- **法律与授权**：公开注册已具备强制勾选、服务端版本快照和同意时间留痕；仍须由法律顾问审核隐私政策、服务条款、退款政策、知识产权、内容责任、用户注销和争议解决条款，确认协议更新后的重新同意规则及第三方模型/支付/邮件/对象存储的数据处理与跨境传输披露。
- **内容安全**：建立违规分类、发布前审核、举报、人工复审、申诉、下架、侵权投诉和审计记录。短剧中的内容确认 Gate 只服务创作流程，不能替代平台合规审核；同时明确年龄限制、禁止用途和 AI 生成标识。
- **监控和值班**：配置就绪探针、CPU/内存/磁盘、数据库连接与慢查询、API P95/P99、5xx、生成成功率、支付失败、退款失败和对象存储容量告警，并演练通知、定位、升级和恢复。
- **备份与灾备**：分别备份 PostgreSQL、本地媒体、S3/OSS 对象、支付配置和加密密钥；在新环境完成恢复演练，核对账号、积分、订单、生成记录、Canvas、短剧和媒体链接，并记录 RPO、RTO 和备份保留周期。
- **容量验证**：在接近生产的反向代理、数据库和存储环境完成 100、500、1000 并发分级压测，覆盖登录、列表、生成任务、SSE、媒体播放、支付回调和后台聚合查询，记录连接池等待、锁等待、慢查询和磁盘增长。
- **异步生成与计费一致性**：使用真实图片、视频、音频和 Agent 渠道验收排队、超时、取消、失败重试、断线恢复、重复提交、任务卡死接管、资产登记和原消费流水退款；确认用户余额、任务状态、生成记录和媒体引用在重启及多实例竞争下保持一致。积分扣费查询优化只能降低数据库压力，不能替代这条财务与任务闭环验收。
- **安全事件响应**：准备模型密钥、支付证书、维护令牌、OSS 凭据、Session、越权访问、私有媒体暴露和个人数据泄露的分级响应手册，演练隔离、取证、吊销、轮换、通知、恢复和复盘。
- **经营主体与成本**：确认运营主体、服务地区、域名/网络资质、支付商户资质、发票税务口径，以及模型、存储、带宽、手续费、失败退款和套餐赠送积分的成本与毛利基线。

## P1 灰度前事项

- **用户权利**：明确注销申请后的正式执行、创作数据和媒体删除、订单/支付法定保留、身份复核和响应时限；数据导出能力不等于注销和数据保留制度已经完成。
- **财务与售后**：建立账单自动获取或周期对账、退款审批、发票/收据、拒付、支付争议、重复扣款、原路退款失败和异常订单处理流程。
- **客服与投诉**：明确客服入口、服务时间、支付问题、内容举报、隐私请求、投诉升级和补偿规则，并为积分调整、退款和账号处置保留操作人、原因和审计记录。
- **权限治理**：当前后台只有普通用户和管理员两类角色。正式团队运营前应确定财务、客服、内容审核、运营和只读审计的最小权限；管理员 MFA 技术能力已接入，但仍需完成生产设备启用与恢复演练，并补齐异常登录告警、退款/积分调整复核和高风险操作二次确认。
- **密钥生命周期**：定义加密密钥、模型密钥、支付证书、维护令牌和 OSS 凭据的创建、保管、轮换、吊销、泄露响应及恢复校验；只恢复数据库和媒体而没有可用密钥不算恢复成功。
- **数据生命周期与成本**：为对话、任务、原始媒体、WebP 变体、临时文件、审计日志、支付记录和 S3 对象设置保留期限、删除触发、法律保留例外、清理任务和删除核验；监控容量、请求、外网下行、CDN/代理和备份成本，并设置异常熔断。
- **通知与故障沟通**：验证注册、验证码、密码重置、支付结果和故障通知的送达，配置 SPF/DKIM/DMARC、退信/投诉处理和站内兜底；准备状态页或公告替代方案、维护通知以及模型/支付暂停授权人。
- **环境与回滚**：隔离开发、预发布和生产的数据库、对象存储桶、支付商户、模型密钥、维护令牌和回调域名；为迁移前备份、冒烟检查、镜像回滚和回滚后的数据兼容保留记录。
- **供应商与权属**：建立模型、支付、SMTP、对象存储和通知服务的合同、价格、配额、数据区域、保留期限、SLA、停服通知和替代方案清单；审核用户内容授权、生成内容权属、第三方训练/留存边界、BUSL-1.1 商业授权、依赖、字体和素材许可证。还要明确模型故障、价格调整、配额耗尽、模型下线或内容安全服务不可用时的降级、暂停生成、用户通知和退款规则。
- **滥用与增长**：定义年龄、地区、可接受使用、批量注册、刷积分、盗用支付和自动化滥用指标，以及冻结、解冻、申诉和误伤复核；现有累计成交与邀请注册面板只作为基础观测，仍须统一正式时间窗、注册、首个成功作品、留存、付费转化、ARPU、复购、退款率和单位作品成本口径。
- **体验与无障碍**：在目标浏览器和 390px/430px 移动端验收键盘焦点、表单错误、对比度、动态状态播报、媒体替代文本、下载行为、长会话、真实媒体和长列表；公布最低支持范围，并补充新用户首次成功生成路径。
- **成本上限与熔断**：在单用户、单任务、单日和全站维度设置模型调用、媒体处理、存储与外网下行上限，并配置上游余额、异常成本、容量和毛利预警；积分余额校验不能替代盗号、上游配额耗尽和异常成本保护。

## 上线判定

1. 任一 P0 事项没有负责人、复核人和真实证据时，不得宣称正式商业上线。
2. P1 事项未完成时，只能按已声明范围进行封闭或灰度运营，并明确人工兜底责任。
3. 每周复核生成成功率、退款率、单位作品成本、存储增长、投诉和供应商异常；发生资金、隐私或内容安全风险时，立即暂停对应模型或支付渠道，保留用户数据和财务记录。
4. 发生上游停服、配额耗尽、异常成本或通知故障时，按预先批准的降级和熔断规则执行，并记录影响范围、退款结果、恢复时间和复核结论。
