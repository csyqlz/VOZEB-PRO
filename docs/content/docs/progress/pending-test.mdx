## 安全与并发加固

- 公共媒体代理与系统渠道 `_media` 不再信任上游 `Content-Type`，会按文件字节识别真实图片、视频或音频；HTML、JavaScript、SVG、未知二进制和超限内容会在响应前拒绝，`application/octet-stream` 中的真实媒体仍可使用。GET、HEAD 和非零 Range 共用 30 秒下载、300MB 总量与 32MB 分段保护，失败会取消上游流并释放并发许可。41 项媒体代理定向测试已通过；仍需用真实大视频、私有对象存储和会返回错误 MIME 的正式渠道复核拖动播放、Range、超时与连接释放。
- 首次数据库初始化和首个管理员创建现在必须提交与服务器 `VOZEB_PRO_INSTALL_TOKEN` 一致的一次性令牌；普通 `createUser` 在空库会拒绝，安装完成后的公开注册始终创建普通用户，并发首管理员请求只能成功一个。安装页会生成令牌并写入可复制配置，公开状态只返回是否就绪；App Compose 与 Render Web 持有令牌，生成 Worker 不再读取完整 `.env` 且不会获得令牌。52 项安装、认证、Compose 与 Render 定向测试及 TypeScript 检查已通过；仍需在干净 Docker、宝塔、外部 PostgreSQL 和 Render 实例完成真实初始化、错误令牌、并发请求、安装后移除令牌与重启验收。
- 系统渠道代理新增方法、路径、逻辑模型绑定、能力和计费类型联合授权：普通用户只能访问当前协议声明或标准协议允许的创建、查询、取消路径，未知请求会在扣费和上游调用前返回 4xx；专项测试覆盖标准文本/图片/视频/音频路径、自定义任务路径、模型解绑、能力错配和未知路径拒绝。仍需在正式渠道配置下逐个复核实际创建、查询、取消和退款流水。
- PostgreSQL 认证在线写入已从完整 AuthDatabase 读改写改为用户、Session、邮箱验证码、积分、CDK、公告和设置的实体级 Repository/事务；积分调整使用用户行锁和幂等流水，资料与余额并发更新不会覆盖 Session 或流水。文件 Provider 继续使用串行 mutation。专项测试覆盖 Repository 映射、事务回滚和真实 PostgreSQL 并发夹具；仍需在多实例和生产等价连接池下压测锁等待与吞吐。
- 支付 Checkout 不再把上游 `formHtml` 直接写入同源窗口。服务端使用标准 HTML 解析器提取有限的 action、GET/POST method 和隐藏字段，过滤脚本、事件和危险输入；表单支付只打开按当前用户订单读取已保存参数的同源提交页，该页使用本次支付商 Origin 的动态 CSP、转义字段和一次性脚本 nonce 自动提交。生产环境拒绝公网 HTTP 支付地址，开发环境仅允许本机 HTTP。专项测试覆盖脚本丢弃、危险协议、结构化字段、订单归属、CSP 和弹窗拦截，真实支付商仍需完成 HTTPS 沙箱下单、回调、退款与对账。
- `/api/auth/session` 只返回站点展示、注册开关、公开计价/默认值、启用逻辑模型和内部系统代理摘要，不再序列化渠道高级协议、上游地址、SMTP、支付密钥、Skill 指令或运营策略。登录、注册、验证码与密码重置限流组合可信代理 IP、规范化账号和设备指纹；代理跳数不足或地址非法时不信任转发头，未知密码重置邮箱与已存在邮箱返回相同成功结构。专项测试覆盖敏感字段反向断言、三维限流和账号枚举边界；仍需在正式反向代理拓扑验证跳数和误伤率。
- GitHub Skill 导入会把分支或 Tag 解析为 40 位 commit SHA，再从同一 commit 读取 `SKILL.md`，保存可选许可证与 SHA-256 内容哈希，并由默认文本模型整理为项目原生规则，导入后默认停用。主应用与文档镜像只在正式 Tag 且质量门禁通过后构建，`latest` 不再由普通分支产生；发布流程生成 SPDX SBOM、使用 Cosign 对不可变 digest 签名并附加证明。仓库已补齐 ESLint、Playwright E2E、Dependabot、CODEOWNERS、Issue/PR 模板和第三方许可证清单；仍需在 GitHub Actions 与 GHCR 正式 Tag 上验证 OIDC、签名和 attestation 可查询。
- 系统 AI 代理普通请求体限制为 4MB、multipart 限制为 25MB，支付回调限制为 256KB；同时检查 `Content-Length` 并对无长度流式请求累计字节，超限返回 413。
- 文本、图片、视频、音频、Agent 和短剧整集合成的并发检查与任务创建已进入用户+任务类型原子锁；PostgreSQL 使用事务 advisory lock，文件 Provider 使用进程内串行队列。仍需在多实例 PostgreSQL 环境执行并发压力验收。
- 商品更新按更新后的最终价格和积分组合重新校验，积分商品不能通过局部更新变成零元商品。
- Docs 已将传递依赖 PostCSS 覆盖到安全版本，`pnpm audit --prod` 无已知漏洞。

## 后台数据性能
